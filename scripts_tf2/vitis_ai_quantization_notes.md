# Vitis-AI 8bit量子化（`my_quantizer.py`）の仕組みメモ

対象スクリプトは、Keras/TensorFlow の YOLOv3-tiny を **Vitis-AI で INT8 量子化**し、KV260 の
**DPU（DPUCZDX8G）**で動かすためのもの。核心は `vitis_quantize.VitisQuantizer` の
`quantize_model(calib_dataset=...)`。ここで実際に何をしているかを、順を追って整理する。

---

## 1. 大前提：量子化するのは「重み」と「活性」の2つ

W×x（重み × 入力）を INT8 化するとき、量子化対象は2種類あり、性質が違う。

- **重み(weights)**: 学習後に**値が確定した既知の定数**。分布を見るのにデータは不要。
- **活性(activations)**: 入力に依存して**実行時にしか値が決まらない**。範囲を知るには
  実データを流す必要がある。

→ **calibration data の本当の仕事は「活性」の範囲を決めること**。重みはデータ無しで量子化できる。
（「重み定数の分布を見て外れ値クランプ」という理解は*重み側*の描写で、calib が効くのは*活性側*。）

---

## 2. `quantize_model` の内部処理（5段）

### (1) グラフの整形（量子化の下準備）
浮動小数モデルを量子化しやすい形に変換する。
- BatchNorm を Conv に畳み込む（BN folding）
- Conv + bias + 活性関数（LeakyReLU 等）を1つの演算に融合
- 各所に **量子化/逆量子化（fake-quant）ノード**を挿入
- DPU が実行できる構成へ整合

### (2) 重みの量子化（データ不要）
各層の重みは既知なので、そのまま **per-tensor・対称・2のべき乗スケール**の INT8 にする。
calib data は使わない。

### (3) calib data を流して「各層の活性分布」を観測
`calib_steps × cal_batch_size` 枚を**前向きに流すだけ**（逆伝播なし・重み更新なし）。
各活性の量子化点で、値の散らばり（min/max やヒストグラム）を溜める。
※見るのは最終出力ではなく、**各層の中間活性（feature map）の分布**。

### (4) スケール（クリップ閾値）の決定 ← ここが核心
溜めた活性分布から、**活性テンソルごとに INT8 のスケール（＝2のべき乗の fix point 位置）を選ぶ**。
単純に最大値を覆うのではなく、**候補の2のべき乗位置をいくつか試し、量子化誤差
（クリップし過ぎる損 ⇔ 丸めが粗くなる損 のトレードオフ）が最小になる位置を選ぶ**。
外れ値を少し切り捨てた方が全体誤差が小さければそちらを採る＝これが「外れ値クランプ」の実体。
重み側も同様に2のべき乗位置を選ぶ。

### (5) 確定して保存
量子化パラメータ（重み INT8 値＋活性スケール）をモデルに焼き込み、`.h5` として保存。
これを後段の Vitis-AI コンパイラが DPU 命令（`.xmodel`）へ変換する。

> 今回のスクリプトは素の `quantize_model` なので、**bias correction** や
> **fast finetune**（calib データで重みを微調整して誤差を減らす AdaQuant 的オプション）は動かない。
> フラグで足せば (4) の後に入る。

---

## 3. fake-quant ノードはどこに・どれくらい入るか

原則：**DPU に渡るテンソルの境界はすべて INT8** でなければならない。
よって量子化ノードは**ほぼ全テンソル境界**に入る。

- **各層の重み**に1つ（Conv / DepthwiseConv / Dense など重みを持つ層ごと）
- **各演算の出力活性**に1つ（融合後の Conv 出力など）
- **ネットワーク入力**に1つ
- **concat（route）/ upsample / add** などデータ移動系の出力にも
  （concat は入力のスケールを揃える必要があるため）

ただし融合（fusion）後の単位で入る。Conv+BN+bias+LeakyReLU は1演算に融合されるので、
そのブロックにつき「重み量子化1つ＋出力活性量子化1つ」。BN は畳み込まれて消え、
**bias は INT8 ではなく INT32 アキュムレータ側でスケール整合**という特別扱い。

**数の目安**：YOLOv3-tiny（Conv 約13層＋maxpool＋upsample1＋concat1＋検出ヘッド2）なら
「Conv 1層あたり 重み1・活性1」で合計おおよそ**数十個**。
フル YOLOv3（Conv 約75層）なら重み＋活性で **~150点**規模。

---

## 4. なぜスケールを2のべき乗にするのか

理由は**再量子化（requantization）がビットシフトだけで済むから**。DPU は固定小数点エンジンで、
INT8×INT8 を掛けると INT32 アキュムレータに溜まる。次層へ渡すにはこれを INT8 に戻す必要がある。

- スケールが**2のべき乗なら、戻す操作は単なる右シフト（`>> n`）**。乗算器が要らない。
- 任意スケール（TensorRT 等）だと、要素ごとに掛け算＋丸めが必要。乗算器を並べると面積も電力も食う。

→ スケールを「各テンソルの2のべき乗位置（fix point）＝整数の指数1個」に制約することで、
requant を全部シフトに落とし、**演算器をシンプル・高速・低コスト**にしている。
add/concat のスケール整合もシフトだけで揃う利点もある。

**トレードオフ**：2倍刻みでしか選べず、クリップ閾値が2×単位で飛ぶので、任意スケールに比べて
最大1bit分ほどダイナミックレンジを損することがある。DPU の INT8 が TensorRT の任意スケール
（＋per-channel）INT8 よりわずかに精度が落ちるのはこのため。8bit は寛容なので実用上は許容され、
代わりに**シフトだけの安いアクセラレータ**が手に入る、という設計判断。

> DPU は **per-tensor（テンソルに指数1つ）＋2のべき乗**、と2重に粗い量子化。
> どちらも DPU を簡単にするための割り切り。

---

## 5. スケールと「量子化データ」の関係

- スケールは **per-tensor**：各**重みテンソル**・各**活性テンソル**にそれぞれ独立のスケールがある。
  活性スケールは calib で層ごとに決まるので、**層ごとに違う値**になるのが普通。
- 量子化モデルの成果物は、**INT8 の重み整数値**と、**スケール（fix point）値（重み側・活性側の両方）**を
  セットで持つ。スケールが無いと INT8 整数は解釈できず、層境界の requant シフト量も決まらないので、
  スケールは量子化モデルの不可欠な一部。

**2段構成に注意**：
- `quantize_model` の出力 `.h5`：実は **fake-quant モデル**＝浮動小数の重み＋量子化パラメータ
  （スケール/fixpoint）を埋め込んだ状態。INT8 を"シミュレート"している段階。
- コンパイラ（vai_c）の出力 `.xmodel`：**真の INT8 重み＋ fixpoint（シフト量）**を DPU 命令として梱包。

どちらの段でも「量子化された重み＋スケール」が一体で持ち回られる。

---

## 6. 推論時の requant とシフト量

DPU の1層の計算：

```
INT8重み × INT8入力 → INT32 で累算 → bias 加算 → 右シフト → 次層の INT8
```

この右シフト量は `shift = 入力fixpoint + 重みfixpoint − 出力fixpoint`。

- **根源的に保存されているのは各テンソルの fixpoint（2のべき乗の指数）**。
  入力 fixpoint（＝前層の出力 fixpoint）、重み fixpoint、出力 fixpoint、bias fixpoint。
- **シフト量はそれらから導出される派生値**で、**コンパイラ（vai_c）が事前計算して DPU 命令に
  定数として焼き込む**。実行時に計算し直さない。命令には
  - `shift_cut`：アキュムレータ(INT32) → 次層 INT8 への丸め（＝上の requant シフト）
  - `shift_bias`：bias をアキュムレータのスケールに合わせるシフト

  といった形で**層ごとの整数定数**として入っている。

→ 実行時の DPU は「累算 → bias 加算 → **保存済みの固定シフトで右シフト**」を、
掛け算なし・分岐なしの固定パイプラインで回す。**全部2のべき乗設計だからこそ requant が
シフト1回で済む**。

---

## 7. まとめ（一言）

- calib data の主目的は **活性の範囲を実データで決めること**（重みはデータ不要）。
- `quantize_model` は「グラフ整形 → 重み量子化 → calib で活性分布観測 → 各テンソルの2のべき乗
  スケール決定 → 保存」を行う PTQ（再学習なし）。
- fake-quant は**全テンソル境界（各層の重み＋各演算の出力活性＋入力）**に入る。
- スケールを2のべき乗にするのは、**requant を乗算なしのシフトで済ませる DPU の都合**。
- 成果物は **INT8 重み＋スケール（fixpoint）**が一体。`.h5`(fake-quant) → `.xmodel`(真のINT8+シフト)。
- これは W8A8 の典型的 PTQ で、8bit が寛容ゆえ **per-tensor＋2のべき乗の粗いクランプで足りる**
  （QuaRot のような回転・外れ値変換は不要）。
